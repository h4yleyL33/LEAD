### Schema (verified by `src/data/audit.py`)

| Column | Type | Description |
|---|---|---|
| `building_id` | int | Building identifier (grouping key) |
| `timestamp` | datetime | Hourly timestamp, local time, 2016 |
| `meter_reading` | float | Hourly electricity consumption (kWh); may be missing |
| `anomaly` | int (0/1) | Ground-truth anomaly annotation |

**Verified facts** are recorded in `results/metrics/data_audit.json`. Anything not present there is an assumption, not a fact.

## Secondary dataset (BLOCKED): Kaggle LEAD competition split

The Kaggle competition `energy-anomaly-detection` (train.csv 200 buildings / test.csv 206 buildings,
1.34 GB) requires an authenticated Kaggle account that has accepted the competition rules.

- Status: **NOT AVAILABLE** — no `~/.kaggle/kaggle.json`, no `KAGGLE_USERNAME`/`KAGGLE_KEY` in env;
  Kaggle API returns HTTP 401.
- Consequence: the exact competition split, `train_features.csv`/`test_features.csv`, and the
  `row_id`-based submission format cannot be used. No leaderboard score will ever be claimed.
- Mitigation: LEAD1.0-small is real, annotated, hourly commercial-building meter data with the
  same three modelling columns, so the scientific pipeline (grouped building holdout, leakage-safe
  features, XGBoost, ROC-AUC) is executed on genuine labels rather than synthetic fixtures.

See `BLOCKERS.md` (B-001) for the user action required to lift this.

## Synthetic data

`data/synthetic/` holds **simulated** geothermal auxiliary-equipment signals generated by
`src/simulation/`. These are *never* real PLTP Kamojang measurements and are *never* mixed into
the training/evaluation of the LEAD model. Any metric computed on them is reported separately and
labelled SIMULATED.
