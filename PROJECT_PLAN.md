# PROJECT_PLAN — AIoT Energy Anomaly Detection (CRISP-DM)

**Project:** AIoT-based anomaly detection for geothermal power plant auxiliary equipment,
using a transferable, leakage-safe machine-learning pipeline.
**Repository:** `E:\project\LAB_AI\AIoT`
**Authoritative specification:** `MASTER_PROMPT.md`
**Plan version:** 1.0 — created 2026-11-09

---

## 1. Scope in one paragraph

Build and empirically validate an end-to-end, reproducible anomaly-detection system for
hourly building-energy telemetry, structured by the six CRISP-DM phases, and *transfer* the
resulting methodology to a simulated geothermal (PLTP Kamojang) auxiliary-equipment monitoring
scenario. The machine-learning model is trained and evaluated on **real annotated data**
(LEAD1.0-small). The geothermal component is a **simulation**, explicitly labelled as such, and
never presented as measured plant data.

## 2. Scientific integrity rules (binding)

1. Every reported number must be traceable to a file under `results/` produced by a script in
   this repository, with a recorded seed and environment.
2. Simulated geothermal signals are labelled `SIMULATED` in code, filenames, figures, tables and
   prose. No sentence may imply they are PLTP Kamojang measurements.
3. No leaderboard claim is made: the Kaggle competition split is unavailable (see `BLOCKERS.md`
   B-001). All metrics are computed on our own grouped holdout of LEAD1.0-small.
4. No citation is invented. Every reference in the manuscript is either (a) verified by reading
   the source, or (b) omitted.
5. Baselines are always reported next to the proposed model. A model that does not beat the
   strongest baseline is reported as such.

| Criterion | Target | Verification |
|---|---|---|
| Reproducibility | Two clean runs produce identical metrics to 6 decimals | `tests/test_reproducibility.py` |
| Leakage safety | No feature at time *t* uses information from *t'* > *t*; peer features use only past windows | `tests/test_features_no_leakage.py` |

## 6. Evaluation protocol (fixed before modelling)

- **Split:** building-disjoint. 200 buildings → 140 train / 30 validation / 30 test, stratified
  by per-building anomaly rate, seed 42. Rationale: the deployment target is *unseen buildings*
  (new meters), so random row splits would overstate performance.
- **Primary metric:** ROC-AUC (threshold-free, imbalance-robust).
- **Secondary:** PR-AUC (average precision), precision/recall/F1 at a *validation-selected*
  threshold, Brier score, recall@FPR≤1%.
- **Uncertainty:** 1,000-sample bootstrap 95% CI on the test set.
- **Missing values:** XGBoost handles NaN natively; no imputation for the tree model.
  Baselines that cannot handle NaN use median imputation fitted on train only.

## 7. Risk register

| ID | Risk | Impact | Mitigation |
|---|---|---|---|
| R1 | Kaggle competition split unavailable | Cannot claim leaderboard parity | Documented in `BLOCKERS.md`; use real LEAD1.0-small; no leaderboard claims |
| R2 | Annotation noise / label subjectivity | Caps achievable AUC | Report ceiling discussion; per-building label-quality caveat in limitations |
| R3 | Building-disjoint generalisation gap | Lower AUC than row-wise splits | Expected and reported; it is the honest number |
| R4 | Leakage via target-derived features | Invalid results | Automated leakage tests; only causal windows |
| R5 | Python 3.14 wheel gaps | Build failure | Verified working: numpy 2.5.4, pandas 3.1.1, xgboost 3.4.1, shap 0.54.1 |
| R6 | Overfitting hyperparameters to test set | Optimistic results | Tuning on train/val only; test touched once |
| R7 | Simulated geothermal data mistaken for real | Scientific misconduct | Hard labelling + code-level guard + prose rules |
| R8 | Compute limits (CPU only) | Slow tuning | Optuna trial cap, early stopping, `tree_method=hist` |
